# リレー

ユーザーはコマンドを実行しない。指示を出すだけである。「リレーで進めて」と言われたら、このセッションがオーケストレーターになり、完了まで回す。ユーザーにコマンドや tmux の操作を頼まない。

## しくみ

- タスクは三種類：本の準備（start-book スキル）、1 ページ（translate-page スキル）、本の完了処理（finish-book スキル）。
- `node tools/relay.js <進捗表> --once` が、次のタスクを一つ選び、新しい `claude -p` のセッションに渡して終わりまで待つ。
  - そのセッションは `--permission-prompts none` で動くので、承認の確認では止まらない。確認が要る操作は断られ、エージェントは別のやり方を探す。
  - 状態が進まなければ 5 分おいて 3 回まで繰り返す。利用上限に当たったら、上限が戻る時刻まで待って続ける。
- 状態はリポジトリにだけある：`pages.json`、README の進捗表の `[x]`、`book.json` と作品一覧。だから引き継ぎファイルは要らず、どこで止まっても、次の起動は続きから始まる。
- このセッションの文脈には、各タスクの短い結果だけが積もる。訳の中身は各セッションの中で閉じる。

## 1. 進捗表を書く

`relays/<名前>.md`。本を訳す順に `## <本のディレクトリ名>` の見出しを並べる。見出しの下には、その本の注意を書く（タスクのセッションにそのまま渡される）。

```markdown
# 3 世紀の文書リレー

## tertullian-apology　テルトゥリアヌス『護教論』（ラテン語）

- 底本：Oehler 1853（archive.org の識別子 …）。英訳は ANF 第 3 巻。
- 『殉教者たちへ』と訳語を揃える。

## origen-on-prayer　オリゲネス『祈りについて』
```

注意に書くのは、セッションが自分で調べると時間のかかることだけ：底本の候補、資料の所在、同じ著者の本との揃え方。手順は書かない（スキルにある）。候補は `CANDIDATES.md` から取る。書いたら `Start relay <名前>` でコミットして push する。

## 2. 回す

1. `node tools/relay.js relays/<名前>.md --status` で、本ごとの進み具合と次のタスクを確かめる。
2. `node tools/relay.js relays/<名前>.md --once` を Bash の `run_in_background: true` で起動し、ターンを終える。1 ページでおよそ 20〜60 分かかる。待つあいだ、出力ファイルを読んだり、ポーリングしたりしない。終わると通知が来る。
3. 通知が来たら確かめる。
   - 出力の末尾の数行と終了コード。
   - `--status` と `git log --oneline -5`。ページのタスクなら、`<本> <節>` と `Improve <本> <節>` の二つのコミットと `research/reviews/<節>.md` があるか。完了処理なら `node tools/check-book.js <本>`。
4. ユーザーに 1〜2 行で報告する（例：「『護教論』chapter-07-12 を訳了（7/40 ページ）。レビューの指摘 14 件のうち 13 件を採用」）。気になる点（判断を記録に残したもの、検証の警告が残ったもの）があれば一言添える。
5. 次のタスクを 2 と同じように起動する。

終了コードが 1 のとき（3 回失敗した、作業ツリーが汚れたまま）は、`cache/relay-logs/` の最新のログの末尾を読んで原因を調べる。道具の不具合なら直してコミットし、再開する。ユーザーの判断が要ることなら、brief-me の形で尋ねる。

## 3. 終わったら

`relay finished` が出たら、`git log` で各本の `Finish <本>` のコミットを確かめ、ユーザーに報告する（訳した本、ページ数、気になった判断）。

## 注意

- タスクは一度に一つだけ走らせる（同じ master に push するので）。
- 進捗表に本を足す・順番を変えるのは、ユーザーの指示があったときだけ。
- ユーザーが途中で別の作業を頼んだら、走っているタスクはそのまま終わらせ、次のタスクは起動せずに止める。再開を頼まれたら 2 から続ける。
