## 手順

1. ページごとに、照合の候補を出す（`<OCR の範囲>` は下の印刷版の行範囲）：
   `node tools/collate.js {{底本}} <範囲> <OCR のファイル> <最初の行>-<最後の行>`
   - 柱（ページ上の書名）やページ番号が候補に混じるときは `--skip '<正規表現>'` で落とす。
   - OCR がひどく崩れていて候補が多すぎる（範囲 1,000 語あたり 150 以上）ときは、まず `--ignore-accents --ignore-punct` で語の違いだけを見て、そのあとアクセントと句読点を見る。
   - 最後の行の similarity が 0.75 未満の本（OCR が崩れている。『トリュフォン』の Archambault 版など）でも、全文を画像で読み比べはしない。`--ignore-accents --ignore-punct` の候補のうち語が違うものと、手順 3 で見つけた箇所だけを画像で確かめる。
2. 候補の多くは OCR の誤りです。電子化の誤りと決める前に、ページ画像で一つずつ確かめる。画像は 1 枚ずつ `node tools/iiif-crop.js <identifier> <IIIF番号> <領域> cache/archive.org/<identifier>/pages/` で取る（領域は `full`、`x,y,w,h`、割合の `pct:x,y,w,h`）。すでにあるファイルは取り直さない。
3. 候補に出ない誤りもある。印刷版の誤植を電子化がそのまま写したもの、語の途中の空き、OCR と電子化が同じ誤りをしたものなど。底本の抜粋を一度通読し、ありえない語形や文法の崩れがあれば、その箇所も画像で確かめる。
4. 記録するのは、語が変わる違いだけ：別の語や語形になるもの（アクセントや気息の違いでも、ἦς と ἧς のように別の語になるものは含む）、語の欠けや重複、語の途中の空き、意味の切れ目が変わる句読点。別の語にならないアクセント・気息だけの違い（ἴνα と ἵνα など）は記録しない。印刷版そのものの誤植も分けて記録する。

## シェルの書き方

実行するまで中身が決まらないシェル（`for` ループ、変数をつないだ URL、`$` を含む URL の curl、`rm`）は書かない。繰り返しは scratchpad に Node のスクリプト（`.js`）を書き、引数を渡して `node` で実行する。

## 作るもの

ページごとに一つのファイル：{{照合の書き込み先}}

```
# <節> の電子化と印刷版の照合（<範囲>）

照合した印刷版：<書誌>（OCR <ファイル> l. <行>〜<行>、画像 <番号>〜<番号>）

| 節 | 電子化 | 印刷版 | 種類 | 確かめた画像 |

| 12.3 | ἐποίησε | ἐποίησεν | 入力の誤り（意味は変わらない） | 0113_pct:0,0,100,50.jpg |
```

種類は「入力の誤り（意味が変わる）」「入力の誤り（意味は変わらない）」「句読点」「印刷版の誤植」のどれか。違いがなかったページも、表の代わりに「食い違いはない。」と書いてファイルを作る。

`research/collation/`、`cache/` 以外は編集しない。コミットしない。
